# Unified L2 cache — P2-018

Four eight-byte lines contain valid/physical tag/dirty/bytes; FIFO stores line
indices. Exact capacity is 32 bytes. Duplicate tags, incomplete FIFO, invalid bytes
and Dirty lines are rejected under the proposed #3 write-through policy. Physical
224..255 bypass L2; translation and I/O routing belong to the caller.

UnifiedL2.reset() creates invalid lines. lookup(cache,pa) returns hit/miss without
mutation or FIFO reordering. begin(cache,basePa) starts a fill; accept(cache,fill,
{pa,value}) accepts only the next byte, remaining pending until byte eight. Only
then is the line installed and the oldest line evicted if full. Cache changes
invalidate outstanding fills.

readLine(cache,request,readBusByte) handles L1I/L1D requests shaped as
{kind:'read-line',level:'L2',basePa,length:8}. It returns cache, response, local events
and {hits,misses} deltas. A hit never calls RAM. A miss requests eight ordered bus
transfers. Responses fit Cristian's InstructionCache.fill API; L1I validates its own
generation. L1D can use the same request format. L1 hits must not call L2.

The coordinator applies counters once on commit. L2 FIFO is independent from page
FIFO. Proposed hierarchy is non-inclusive: L2 eviction alone does not invalidate L1.
Writes/frame reuse must update or invalidate every physical copy through #3/#15/#19.

For Step, persist fill and call accept for each bus micro-step. readLine is a full
transaction helper, not one #6 clock step. Its callback stages a candidate and returns
{pa,value,event}; it must not persist external effects itself. Discard the candidate
on failure. Cache-local events must be associated with global events by the coordinator.
